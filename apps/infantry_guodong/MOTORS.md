## 1. CAN 总线分配总览

| 板 | 总线 | 挂载设备 | 说明 |
|---|---|---|---|
| 云台板 | **CAN1** | DM-J4310(Pitch) + M3508×2(摩擦轮) | 命令帧 0x200 / 0x02 |
| 云台板 | **CAN2** | GM6020×1(云台 Yaw) + **板间通讯(旧 CToC,新 0x310/0x311)** | 0x205 反馈 / 0x1FE 命令 |
| 底盘板 | **CAN1** | M3508×4(四轮) + M2006×1(拨盘) | 命令 0x200(四轮)/ 0x1FF(拨盘) |
| 底盘板 | **CAN2** | **板间通讯** + 旧代码还解析 GM6020 0x205 反馈 | ⚠ 说明见 §5 |

> **关键拓扑事实**:旧底盘板的 `Mecanum.c` 直接读取 `GM6020_MotorStatus[GM6020_1-0x205]`(Yaw 电机反馈)做"跟随/小陀螺判定",而 Yaw 电机是由**云台板**驱动的 ⇒ **两板的 CAN2 是同一根总线(板间互联总线)**,Yaw 电机与板间帧共用它。
> 移植后推荐改为"云台板把 `offset_ecd` 放进 0x310 下发",底盘板不再直读 Yaw 电机(见 §5)。

**底盘关键参数**
- 底盘是**全向轮**:轮子 ±45°、**40cm × 40cm 正方轮距**(旧工程文件名叫 `Mecanum.c`, 但实车不是麦轮)
- 逆解统一用**模块层 `Chassis_Omni_Calc`**(`modules/algorithm/chassis_type.c`): 切向 X 型布局,
  自转项 `vw*chassis_radius`(`chassis_radius = √((x/2)²+(y/2)²) = 0.2828 m`), 四轮**同号** ⇒ 能自转。
  (模块层早期是径向布局 `vw*(a-b)`, 正方轮距下自转恒为 0, 已改掉; 旧工程 `Mecanum.c` 的四项与切向 X 型标准逆解逐项一致)
- ⚠️ 轮序见上: `chassis_motors` 是 `[LF, LR, RR, RF]`, 和模块层一致, 不需要重排
- 轮序: `chassis_motors = [LF, LR, RR, RF]`, 直接对齐模块层 `Chassis_Omni_Calc`, 所以初始化时写的 tx_id 是 **1/4/3/2**。
  每个轮子自己的 tx_id 没变(LF=1 RF=2 RR=3 LR=4), 只是数组下标顺序变了。
  在线位图 `wheels=0x..` 的位序是 bit0=LF bit1=LR bit2=RR bit3=RF; 蜂鸣次数仍按轮位(LF=1 RF=2 RR=3 LR=4)
- ⚠️ 正解 `Chassis_Omni_Fwd` 仍是旧的径向公式(`a-b`、vw 组合有 bug), 尚未同步, 不要用于里程计
- 几何:轮半径 `8.1 cm`、半距 `a = b = 20 cm`
- ⚠️ 切向 X 型下"前进"**不是四轮同向**: 纯 vx 时 LF/LR 反转、RF/RR 正转 —— 这是正常的, 别去"修"
- 旧增益:四轮速度 Kp `11.8`(限幅 ±15000,**RPM 量纲**)、跟随 Kp `0.004`(限幅 2/5)、拨盘速度 Kp `5.0`(限幅 ±10000,**RPM 量纲**)
- 拨盘单发:**输出轴转过 > 43.0°** 即停;单发/连发转子目标 `6480 RPM`;连发条件 `Remote_SWC == 0x70F`
- 摇杆映射:`Mecanum.c` 实际是 `(raw/784)*3.0` 再按半径 3.0 做圆形限幅 ⇒ 满杆 **3.0 m/s**(`Parameter.h` 的 `Mecanum_LeverSpeedMapRate=1.2/660` 无调用者)
- 小陀螺角速度:`5.0 rad/s`

## 4. 框架参数怎么填(重要!)

`Motor_Init_Config_s` 里三个字段必须自洽:

| 字段 | 含义(框架 `motor_dji.c:120-126`) | 换算公式 | 本车取值 |
|---|---|---|---|
| `gear_ratio` | 减速比 | 机械实际值 | M3508 **15.7647**(268/17,非标准 19.2!) / M2006 **36** / GM6020 **1** / DM4310 **10** |
| `torque_constant` | **转子侧**转矩常数 (N·m/A) | `输出转矩常数 ÷ 减速比` | M3508 `0.2463/15.7647 = 0.01562`;M2006 `0.18/36 = 0.005`;GM6020 `0.741`;DM4310 `0.093` |
| `max_torque` | 输出侧力矩上限 (N·m),同时是控制输出限幅 | `最大电流 × 输出转矩常数` | M3508 `20A×0.2463 ≈ 4.93`;M2006 `10A×0.18 = 1.8`;GM6020 `3A×0.741 = 2.223`;DM4310 `10`(TMAX) |

旧工程给的常数(可直接对照):
```c
// M3508.h
#define M3508_StandardReductionRatio (3591.0f/187.0f)   // 19.203
#define M3508_ReductionRatio         (268.0f/17.0f)     // 15.765  ← 实车
#define M3508_StandardTorqueConstant 0.3f               // 输出侧(标准齿)
#define M3508_TorqueConstant (0.3f*M3508_ReductionRatio/M3508_StandardReductionRatio) // = 0.2463 输出侧
// M2006.h: 减速比 36:1,转矩系数 0.18 N·m/A(输出侧)
// DM_J4310.h: PMAX 12.5 / VMAX 30 / TMAX 10
```

**`tx_id` 语义(框架自动推导 `rx_id`,不要手填)**
- M3508 / M2006:`tx_id` = **电调 ID(1~8)**;`rx_id = 0x200 + tx_id`;ID 1-4 走 `0x200` 帧、5-8 走 `0x1FF` 帧。
- GM6020(电流模式 `GM6020_CURRENT`):`rx_id = 0x204 + tx_id`(ID1 → 0x205);命令走 `0x1FE`(ID1-4)/`0x2FE`(ID5-7)。
- 达妙:命令 ID = `tx_id + 模式码`(MIT=0x000),反馈 ID = `rx_id`(Master ID,必须 > `tx_id`)。
  - DM-J4310(ID 2):`tx_id = 0x02`,`rx_id = 0x12`。

## 5. 两板 CAN2 共总线问题与处理

**现状**:底盘板通过 CAN2 直读云台 Yaw 电机反馈(0x205)判断"跟随/小陀螺"。

**移植二选一**:
- **方案 A(推荐,框架范式)**:云台板把 `offset_ecd` 放进 `0x310` 帧下发,底盘板用 `offset_angle` 做跟随(chassis_func 用 PID 跟 `offset_angle`),**不再需要 GM6020 反馈**。优点:板间帧自解释、底盘板不必依赖共总线拓扑。
- **方案 B(保持旧行为)**:底盘板仍注册一个 GM6020 设备到 CAN2 只读反馈(不发送),继续用其 `Position` 做跟随与小陀螺判定。
  ⚠ 框架 `bsp_can` 要求**同一总线 rx_id 唯一**,0x205 与板间帧 0x310/0x311 不冲突,可共存。

两种方案在骨架里都留了接口(见 `chassis_board/chassis/chassis_func.c`)。
